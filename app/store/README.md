# Store assets

Graphics and screenshots for App Store Connect and the Google Play Console. What to type into the
consoles, and why, is in `../../docs/STORE.md`; the release steps are in `../../docs/RELEASE.md`.
Everything here is generated by the two scripts below, so regenerate rather than edit by hand.

## Graphics (`graphics/`)

| File | Size and format | Where it goes |
|---|---|---|
| `graphics/play-icon-512.png` | 512 x 512, 32-bit PNG (RGBA, opaque), full bleed (Google applies its own mask) | Play Console, Store listing, App icon |
| `graphics/play-feature-graphic.png` | 1024 x 500, 24-bit PNG without alpha: the icon, "Cliffword" in Newsreader, "Finish the sentence out loud" in Inter | Play Console, Store listing, Feature graphic |

The App Store takes its icon from the build (`assets/icon.png`, 1024 x 1024, no alpha), so App
Store Connect needs no separate upload.

The mark is `../assets/brand/mark.svg`: two rows of word tiles on ink, and the story stops at a
dashed amber gap with three dots. `../assets/brand/icon.svg` is the whole icon as one SVG
(generated). The same script writes the app's icons in `../assets/`: `icon.png`,
`adaptive-icon-foreground.png` (the mark inside the central 66 % circle), `adaptive-icon-background.png`
(ink), `adaptive-icon-monochrome.png` (white mark, for Android themed icons), `splash-icon.png`
(the rounded icon, small enough for Android 12's circular splash mask) and `favicon.png`.

Regenerate (needs Playwright with Chromium, which is not an app dependency:
`npm i -g playwright && npx playwright install chromium`):

```bash
npm run icons                                  # from app/
node scripts/make-icons.js --preview /tmp/icon-previews   # also the icon at 29, 58 and 120 px
```

## Screenshots (`screenshots/`)

Six screens, in this order on both stores, for three sizes:

| # | File | Screen (gallery fixture) |
|---|---|---|
| 1 | `<device>/1-story-cliff.png` | The story stops at a cliff: tiles, the dashed gap, "Hold anywhere and say it" (`b1`) |
| 2 | `<device>/2-landing.png` | Where the answer landed: the surprising-to-expected line (`b2`) |
| 3 | `<device>/3-self-repair.png` | A learner turn with heat on the unexpected words and the self-repair card (`a2`) |
| 4 | `<device>/4-music-library.png` | The Music library (`c3`; Android: `c3-android`, "Not available on Android yet") |
| 5 | `<device>/5-lyric-cliff.png` | A lyric line at its cliff, "SING IT" (`c1` with the Apple Music bar; Android: `c1-manual`, no player) |
| 6 | `<device>/6-profile.png` | Profile: minutes spoken today, the week, words understood, the skill mix (`profile`) |

| Folder | Pixels | Store slot |
|---|---|---|
| `iphone-6.9/` | 1320 x 2868 (440 x 956 pt at 3x) | App Store, 6.9-inch display (required) |
| `iphone-6.5/` | 1284 x 2778 (428 x 926 pt at 3x) | App Store, 6.5-inch display (optional when the 6.9-inch set is there) |
| `android-phone/` | 1080 x 2160 (432 x 864 dp at 2.5x) | Play Console, Phone screenshots |

The Android set is 2:1, not a 20:9 phone frame: Play refuses a screenshot whose long side is
more than twice the short side (1080 x 2400 would be 2.22). At 1080 x 2160 it is also above the
1080 x 1920 that Play asks for before it features an app.

The screens are the app's real views (`src/features/*`) rendered from the dev fixture gallery
(`/preview/<fixture>`) of a web export, on made-up content only: the "Luna de Santurce" song by
the made-up Rayo K. and the market story. No real song, artist or album art. The gallery index
and other dev routes are never in the frame; the shots have no status bar and no tab bar (the
fixtures render the screen body, as the design previews do), and the story's small "Report this
sentence" footer link is hidden (it would push the Android landing's chips below the fold). Each file is a PNG under 1.5 MB;
the script writes a high-quality JPEG instead if one ever grows past that (both stores take
JPEG).

Regenerate (from `app/`; needs Playwright with Chromium):

```bash
npm run screenshots                                        # = node scripts/store-screenshots.js --build
node scripts/store-screenshots.js --web <export-dir>       # capture from an existing EXPO_PUBLIC_PREVIEW=1 export
```

`--build` runs `EXPO_PUBLIC_PREVIEW=1 npx expo export --platform web`. The script serves the
export with a small static server that answers unknown paths with `index.html`, opens each
fixture as a touch phone in Chromium, waits for the screen's testID and the fonts, and saves
`<device>/<n>-<name>.png`. Change the screens or sizes in `SCREENS` and `DEVICES` at the top
of the script.
